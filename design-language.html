Design language

BrickYard

A brick is a small, warm, over-rounded object that clicks. The interface is made of the same thing.

01 — The idea

Warm shapes, disciplined chrome

Surfaces are rounded and warm, never grey and never sharp. Controls are pills you press. Panels float over the scene as rafts rather than walling it in. The most saturated colour on screen belongs to the bricks — everything the app draws around them stays a step quieter.

The other half: this is a real editor with a large operation set — multi-select, rotate about connection axes, group, mirror, recolour, isolate, undo across all of it. So the chrome is disciplined. Playful in its shapes, matter-of-fact in its words.

03 — Theme

Two themes, one set of ramps

Dark is the default: a cream viewport washes out sand, tan and light grey parts, which are a large share of the corpus. Set it with data-theme on <html> — never per component, never with a media query alone. Components reference semantic tokens (--by-panel), never palette ramps (--color-neutral-800); the theme switch re-points the semantic layer only.

04 — Colour

Three ramps, no grey

Terracotta is the action colour — primary buttons, selection, focus, the ghost, the active tool. Sage is a real second voice, and it means structure: connection points, select-connected, the graph, what is holding a piece up. Neutral is warm sand through deep brown; there is no true grey in BrickYard.

One perceptual lightness scale across all three, so step 400 of any role carries the same visual weight as step 400 of any other. Terracotta on the cream ground clears 3:1, not 4.5:1 — enough for icons, large text and chrome. For accent text at paragraph size use --by-accent-text, a deep ramp step.

The LDraw palette is data, and we don't reinterpret it. A swatch shows the real LDraw RGB, which means it can be any colour at all — including ones that clash with the theme. So the selected ring is drawn in the theme accent outside the swatch, never as a tint on it, and LDraw's finishes get a marker rather than a colour change.

06 — Shape, space, motion

Round, airy, and quick

A real brick has roughly a one-third corner fillet on its stud pitch, and the UI keeps that feel. Sharp corners exist in exactly one place — the viewport, where rounding would clip geometry.

lg 28

Hairline-only geometry is not welcome: a border is the last resort after space and surface change have both been tried.

A 4px base at 1.10 density. Controls are 32px; nothing clickable is smaller. Panel rails are 268px. When something feels cramped, add space before you add a line.

Toy-like means one specific thing: a snap has a tiny overshoot, as though the piece were pulled the last fraction of a millimetre by the connection rather than pushed there by software. That is --by-ease-snap. Everything else is fast and flat — 80ms hover, 140ms reveals, 220ms dialogs. The ghost never tweens between candidates; Tab cuts. The camera is damped per frame in scene/, never transitioned in CSS.

08 — The viewport

Snapping is shown by snapping

The ghost follows the cursor and locks to the mated transform crisply, and that is the feedback. No mate-count badge, no floating candidate list, no numeric readout hovering over the model. If the ghost lands where the user meant, a badge tells them nothing; if it doesn't, a badge doesn't help. The work goes into the landing, not the label.

The scene reads its overlay colours from computed style, so hover, selection and ghost tints re-theme with the chrome rather than being hard-coded in scene/. Chrome floats over the viewport with a gutter to the window edge; the marquee is the only overlay drawn in CSS.

10 — The mark

A 2 × 2 brick, three-quarter view

The smallest object in the corpus that is unmistakably a brick and still shows all four studs. Three steps of the terracotta ramp for the three visible faces, two more for the studs, and a rounded silhouette from stroking each face in its own fill.

The lockup is the mark with BrickYard in Caprasimo, mark height equal to cap height, gap of --by-space-3. One colourway — don't outline or recolour it per context. The favicon is the same mark on a cream tile at 86% so it survives 16px.

11 — For agents

Eight rules

  1. Never write a raw value. No hexes, no font names, no px a token already carries. If the token doesn't exist, add it to tokens.css.
  2. Reference semantic tokens, not palette ramps. --by-panel, never --color-neutral-800. Anything reaching past the semantic layer breaks in dark mode.
  3. The bricks are the brightest thing on screen. No chrome surface may compete with the model.
  4. Nothing sharp except the viewport. Anything pressable is a full pill.
  5. CSS never animates the render loop. Ghosts, gizmos and camera live in scene/.
  6. Every operation has a keyboard path, and the UI says what it is.
  7. No spinners where we know the number.
  8. Theme with data-theme on <html> — never per component.

Snap candidate scoring, ghost behaviour and camera feel are product decisions, not style ones. This document can tell you what colour the ghost is. It cannot tell you whether the ghost landed where someone meant.
